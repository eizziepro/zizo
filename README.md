# Zizo Donor and Surrogacy

Multi-page static HTML + Tailwind CSS + Vanilla JavaScript ES modules application with a Supabase backend (`Postgres`, `Auth`, `Storage`, `Row Level Security`, `Edge Functions`, `pg_cron`) and an isolated Node development test harness.

> [!WARNING]
> **CRITICAL SECURITY NOTICE**: The default demo passwords previously published in earlier repository commits (`ZizoOwner2026!`, `ZizoCoord2026!`, `ZizoEditor2026!`) must be treated as **COMPROMISED**. Never use or reuse these credentials anywhere. All production accounts must use unique, strong passwords managed directly in Supabase Auth with mandatory TOTP multi-factor authentication (MFA).

> [!IMPORTANT]
> **REPOSITORY VISIBILITY RECOMMENDATION**: This repository should be configured as **Private** in GitHub repository settings to protect application configuration, data contracts, and clinical coordination policies.

---

## Architecture Overview

- **Frontend**: Static HTML generated by `build.mjs` using Vanilla JavaScript ES modules in `src/site/` and CSS compiled by `@tailwindcss/cli` from `src/styles/main.css` and `src/styles/tokens.css`.
- **Backend (Production)**: Supabase Postgres with Row Level Security (RLS) on all tables, Supabase Auth with mandatory TOTP MFA, Storage buckets (`site-media`, `private-docs`), and Deno Edge Functions for all public form submissions and transactional interactions.
- **Local Development**: An isolated local development harness runs on Node/Express for offline testing. When running locally, demo staff accounts are seeded dynamically using credentials defined in `.env` (`LOCAL_OWNER_PASSWORD`, `LOCAL_COORD_PASSWORD`, `LOCAL_EDITOR_PASSWORD`). If unset, random credentials are generated on startup and printed to the local console.

## Quick Start (Local Development & Preview)

1. **Install dependencies**:
   ```bash
   npm install
   ```

2. **Configure local environment**:
   ```bash
   cp .env.example .env
   # Edit .env to set your secrets and local development credentials
   ```

3. **Build responsive assets, compile Tailwind CSS, and prerender static HTML**:
   ```bash
   npm run build
   ```

4. **Run unit tests**:
   ```bash
   npm test
   ```

5. **Start the local preview server**:
   ```bash
   npm run dev
   ```
   The site is available at `http://localhost:3000`.

## Staff Portal & Authentication

Navigate to `/admin/` to access the Staff Portal:

- Upgraded to a production-grade single-page application built with **React 19**, **TypeScript**, **Vite**, **Tailwind CSS v4.3**, and **Untitled UI** design system components (`@untitledui/icons`, `react-aria-components`).
- In production, staff users authenticate via **Supabase Auth** with mandatory TOTP enrollment and challenge verification before session creation.
- Staff roles strictly define access boundaries enforced both in the UI and via Postgres Row Level Security (RLS):
  - `owner`: Full platform management (site settings, team management, audit log, services, blog, FAQs, reviews, inquiries, applications, bookings, subscribers).
  - `coordinator`: Intended parent and surrogate pipelines (bookings, availability, consultation types, inquiries, applications, subscribers).
  - `editor`: Journal, services, and educational resources (services, blog posts, FAQs, reviews moderation).
- PII protection: Emails and phone numbers in list tables are masked by default (`a***@gmail.com`, `+234 *** *** 1234`), with a "Reveal" action that logs every unmasking event to the immutable `audit_log`.
- Inactivity security: Sessions automatically lock after 30 minutes of inactivity, with a 2-minute modal countdown.

## Supabase Production Setup

1. Copy `.env.example` to `.env` and populate:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `RESEND_API_KEY`
   - `TURNSTILE_SITE_KEY`
   - `TURNSTILE_SECRET`
   - `DEPLOY_HOOK_URL`

2. Apply Postgres migrations in sequence via the Supabase CLI:
   - `supabase/migrations/001_schema.sql` (Schema, `btree_gist` exclusion constraints, storage buckets, `pg_cron` jobs)
   - `supabase/migrations/002_rls.sql` (Row Level Security across all tables, denying anonymous reads on sensitive tables)
   - `supabase/migrations/003_seed.sql` (Initial site settings, consultation types, legacy testimonials, categories)
   - `supabase/migrations/004_admin_upgrade.sql` (Services table, site_pages registry, faq_assignments table, staff profile fields, avatars storage bucket, RLS policies)

3. Deploy Supabase Edge Functions:
   ```bash
   supabase functions deploy create-booking
   supabase functions deploy send-reminders
   supabase functions deploy submit-form
   supabase functions deploy submit-review
   ```

4. Deploy static frontend to Cloudflare Pages or Netlify:
   - Build command: `npm run build`
   - Publish directory: `dist`
